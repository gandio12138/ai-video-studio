# AI 漫剧前期工作室｜ChatGPT + Codex CLI

版本：1.0；资料核对：2026-09-10。

**先读 START_HERE.md；实际要复制的完整提示词在 PROMPT_LIBRARY.md。**

这套包帮助你从小说/构思走到可检查的前期材料。六个 manju-* skill、提示词、模板和示例是本次定制内容，不是 OpenAI 官方内置漫剧技能，未声称有商业出片验证。
不内置模型，不运行本地生图，不需要 CUDA、Docker、ComfyUI、API 密钥或外部 Python 包。ChatGPT/Codex 自身的联网模型和使用额度仍按你的现有服务执行。

## 一、最小工作流

原创构思 / 已有小说片段 → 大纲与人物目标 → 场景剧本与对白 → 独立剧情检查 → 文字镜头表与资产需求 → 视觉设定确认 → 生成/局部编辑提示词。

重要的不是一步把故事变成视频，而是每个阶段有固定输入、固定输出和人工确认点。实际生图、图生视频与剪辑留到文字试作通过之后。

两种入口都支持：已有小说按原文证据拆解；还没小说则先做原创方案、人物和章节大纲，用户选定后可以按章写正文。不要先为试作写完一部长篇。

## 二、六个技能

| Codex 调用名称 | 用途 | 主要输出 |
|---|---|---|
| $manju-story | 小说事实拆解/原创立项、大纲、人物目标、因果与伏笔 | 01_story/ |
| $manju-script | 场景剧本、心理转动作、对白保真压缩与朗读估算 | 02_scripts/ |
| $manju-audit | 剧情、知识状态、时间、道具、空间与镜头可执行性检查 | 07_reviews/ |
| $manju-shots | 景别、机位、动作、台词、采用时长、连续性与素材清单 | 03_shots/ |
| $manju-visual | 角色定妆、服装版本、场景布局、道具与参考图计划 | 04_visual/ |
| $manju-prompts | 人物/场景/镜头静帧、参考合成与局部修改提示词 | 05_prompts/ |

`.agents/skills` 是按当前官方文档配置的本地项目目录。`SKILL.md` 含 name、description 和执行约定。原始文档链接见 SOURCES.md。
这些技能有意保持文字流程，不自动下载/执行第三方脚本。只有可选的 tools/check_shots.py 做确定性格式与数值检查。

## 四、Codex 启动与兼容排查

将完整文件夹放到桌面，在终端运行：
```bash
cd ~/Desktop/ai-manju-studio
codex
```

然后在 **Codex 交互输入框** 使用 `/skills` 查看技能；用 `$manju-story` 等名称明确调用。这些不是普通 shell 命令；不要在 shell 中直接执行 `$manju-story`。

未发现技能时：先确认当前工作目录就是项目根目录、`.agents/skills/*/SKILL.md` 没被漏拷贝，再重启 Codex。可在普通终端用 `codex --version` 查看本机版本，对照当前官方文档排查。
仍不识别时可以显式让它读取 `.agents/skills/manju-story/SKILL.md` 并执行。这是读取文件的兼容办法，不代表自动技能发现已经修复。是否升级和如何升级，按你的实际安装渠道决定，本包不自动更新全局 CLI。

不要把项目的 AGENTS.md 覆盖到 ~/.codex/AGENTS.md，也不要直接把六个技能零散复制进全局技能库：本包技能引用了项目里的 templates、PROJECT、STATE 等文件。

## 五、分阶段调用示例

以下每段分别使用；完成并确认上一段之后再调用下一段。路径、集号与版本以实际文件为准。

### 阶段1：大纲与人物
```text
$manju-story 读取 PROJECT.md、STATE.md 和 00_source/chapter_001.txt，只做原文事实表、第一集大纲、人物目标与因果链。标注新增设定，保存草案，不写分镜。
```
原创入口则改为：
```text
$manju-story 我还没有小说。按 PROJECT.md 的题材和制作限制，给最多三个原创故事方案；写主角目标、阻力、代价和因果链，等我选一个，不直接写长篇。
```

### 阶段2：剧本与对白
```text
$manju-script 使用 STATE.md 记录的已确认大纲与人物表，为 EP01 写场景剧本和对白压缩对照，保存新版本。不要改核心因果，给粗略朗读估算与未确认项。
```

### 阶段3：剧情审校
```text
$manju-audit 检查 EP01 当前剧本与其上游资料，给证据、位置、严重度、最小修复和待证实问题；不要直接重写全稿。审校结论不替代我的确认。
```

### 阶段4：文字分镜
```text
$manju-shots 把已确认的 EP01 剧本拆成镜头表，按 templates/shot_fields.md 生成 JSON 和 Markdown，计算采用总时长。资产缺失只登记 planned；无视频模型时 generation_duration_s=null。运行可用的本地校验并解释提醒。
```
之后可再用 manju-audit 做镜头连续性复核。

### 阶段5：视觉设定
```text
$manju-visual 按已确认人物和 EP01 镜头需求，先为 C001、C002 与 L001 做文字定妆卡、场景布局和主参考计划。未在原文明确的视觉部分标创作补充。先不要生成图片。
```

### 阶段6：提示词
```text
$manju-prompts 按已确认视觉设定，为 C001 主定妆、L001 空场景和 EP01_SH001 分别写任务单。目标模型暂未指定，只写通用中文；列需要上传的参考图、固定项和验收标准，不调用生图。
```

## 六、ChatGPT 与 Codex 的分工

建议用 ChatGPT 讨论选题、读剧本、挑修改方向；用 Codex 管理文件、版本、固定格式和校验。二者并非能力上的强制分界，而是让你容易管理的分工。

在普通聊天中新建 Project，把 CHATGPT_PROJECT_INSTRUCTIONS.md 正文放入项目指令。先上传 PROJECT.md、STATE.md、PROMPT_LIBRARY.md 和本轮原文；之后按任务补充当前已确认大纲/人物/剧本，不必一次上传全部文件。

这套包没有搭任何自动同步。你在 ChatGPT 确认的稿件，需要手动保存/上传，或明确告诉 Codex 以哪个版本回写。不要依赖同名文件自动代表“最新版”。本地工作室和 ChatGPT 项目上传文件中存在冲突时，先比较版本和用户决定。

普通 Project 中上传文件是提供上下文，不等于安装本地 `.agents/skills`。本包没有插件商店 manifest；无需为了文字工作先研究插件分发。
临时聊天不适合保存这个长期项目；实际使用 Projects 和生图工具时应切换到功能可用的普通聊天环境。

## 七、镜头表和素材管理

每镜包含景别、机位、动作、对白/旁白、音效、采用时长、计划生成时长、素材编号、连续性与后期备注。
结构化 JSON 不等于 ComfyUI 工作流，也不是生图/视频接口请求。要接某个模型，仍需单独写适配层并核对当前支持参数。

`C001` 是人物、`L001` 是可重复使用的地点、`P001` 是道具。`SC01` 是剧本场次，`EP01_SH001` 是镜头。这些编号只是生产管理标签，不能代替上传真实参考图。
素材的 planned / generated / approved 严格区分；尚无文件写 path=null。没有实际查看参考图、没有执行生成，就不能声称完成。

先确认角色主图，再派生角度和表情；先固定场景门窗布局，再做镜头构图。局部修改一次只设一个主要目标，并检查非目标部分。提示词与参考图可以帮助控制结果，但不能保证每个模型绝对保持身份或逐像素保留背景。

## 八、可选校验

只有已安装 Python 3 时才需要这一小步；文字工作本身不要求你安装它。

在项目根目录：
```bash
python3 tools/check_shots.py examples/watch_note/shots.json --assets examples/watch_note/assets.json --root examples/watch_note
python3 -m unittest discover -s tests -v
```

示例预期6镜、30秒，无格式/数值错误；素材未生成会明确提醒。测试覆盖重复镜号、缺字段、未知资产、非法时长、空模板、虚假已生成状态、越界路径、实测声音超时等。
脚本不联网、不写文件。只检查字段、编号、时长、引用、已登记文件存在性和对白粗估；不验证原文引用真假、剧情因果、授权、真实图像质量或用户是否真的批准。真实配音得到后用录音秒数替换粗估。

## 九、试作边界与检查点

建议先只做一章/约1500–3000字片段，或一个原创冲突单元；正式项目默认60秒是可改的试作建议，不是行业规则。选故事与确认大纲之前，不建议先批量做角色图或整季分镜。

本包的文件结构、六个技能元数据、JSON 示例与校验脚本已在制作环境检查；未在你的 Mac、你的 Codex 版本或任一生图模型上做端到端出片测试。安装成功、脚本通过和作品好看是三件不同的事。

原稿不要覆盖，确认过的设定用新版本更改。上游变化时重新检查下游。公开发布/商业交付前，另核实原稿及图像、音乐、音色等素材权限与平台要求；本包没有替你取得这些授权。

外部资料和平台当前用法：SOURCES.md。要研究现成技能/插件，先看官方资料，不自动运行不明来源安装脚本，不在提示词或仓库中写入密钥。
