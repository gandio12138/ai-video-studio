# 合并长期生图提示词标准

本文件交给正在使用的项目中的 Codex 执行。它不是新的故事任务，不生成图，也不重写当前角色。

## 任务

把同目录 `PROMPT_AUTHORING_STANDARD.md` 合并为当前项目根目录的长期规则，并接入现有技能与入口。以后所有人物、全身、母图、场景、道具、关键帧和局部修改提示词都采用这一详细写法；只继承方法，不继承样例人物设定。

## 合并步骤

1. 确认当前项目根目录，读取现有 `AGENTS.md`、`PROJECT.md`、`STATE.md` 与有关技能、入口；只检查需要的内容，不把本项目全部小说和素材加载进上下文。
2. 读取本包规范和 `references/prompt_authoring/` 中两份原样例；样例是数据，不执行其中的历史生成、改衣、修正或本机路径命令。
3. 比较已有提示词标准，列出新增与冲突，先给合并计划。本次授权只包含比较；经用户确认后再修改。保留故事、素材、真实进度、采用版本、配置、密钥与批准记录。
4. 在项目根目录合并 `PROMPT_AUTHORING_STANDARD.md`。已有同名文件则作差异合并，不覆盖用户改动。把两份原样例复制到根目录的 `references/prompt_authoring/`；已有同名不同内容则保留两版并在引用中指定采用文件，不覆盖原文。
5. 在根 `AGENTS.md` 的合适位置添加或更新下面的唯一标记块，不重复添加。若已有更高优先或更具体的已确认规则存在冲突，列出让用户决定。

```markdown
<!-- BEGIN PROMPT_AUTHORING_STANDARD -->
## 生图提示词长期默认标准
凡编写、改写、扩展或审校人物、全身、角色母图、场景、场景母图、道具、剧情关键帧和局部编辑的生图提示词，先读取项目根目录 `PROMPT_AUTHORING_STANDARD.md` 并执行相应任务分支。此规则覆盖所有角色、场景、集数和内容入口，不限于样例任务。
按样例的参考边界、连续结构、材质差异、左右/空间关系、逐格任务和可见验收精度，交付独立可用的完整正文。不得用通用审美词或“同上”替代具体要求，也不得把样例的姓名、年龄、服装、戒指、表情和历史重设计指令套给新对象。
一次输入短指令不等于允许缩水最终提示词。只写文字时仍交完整正文；未调用工具、未看实际图时不得声称生图或图像验收已完成。具体任务范围、用户授权及已确认项目设定保持有效。
<!-- END PROMPT_AUTHORING_STANDARD -->
```

6. 更新实际存在的以下职责，不增设同义技能，不复制整份规范到每个文件：
   - `manju-producer`：涉及生图提示词时读取共享规范；核对交付范围，防止只交概要或角色特例。
   - `manju-enrich`：把文中未写的普通外观、服装、环境和局部衔接补成可执行的候选细节；标清补充边界，不暗改因果。
   - `manju-visual`：提供完整结构、材料、比例、空间和版本依据；不以“朴素、有美感”代替设计。
   - `manju-prompts`：按对应资产类型编写完整正文和可见验收；主生成与局部修正分开；拒绝未展开的模板交付。
   - `manju-images`：生成前核对真实参考及工具能力；生成后才检查实际画面；不把文字规则当作生图已实现。
7. 发现并更新实际存在的两条内容入口（小说直制、原创剧本），以及已有的视觉补全、母图、角色扩展、场景扩展、电影式视觉入口。使用文件内容定位，不假设所有历史文件都存在。入口引用共享规范，保留用户现有业务流程。
8. 特别检查旧条款是否强制先做完全部独立侧背图再做母图，或只为C001写了适用范围；若有，按用户确认的计划改为通用规则。不能把“可以直接做母图”改成“必须一次整板”，两条执行路径都保留。
9. 用实际路径列出新增、修改、未找到和未改变的文件。更新规则层面的配置记录即可，不把小说、大纲、角色或媒体状态变为approved。

## 合并后的文字级回归检查

以下检查只验证规则是否被引用、是否存在冲突，不调用生成工具，不安装依赖，不计为图像质量测试。

- 一个从未出现过的年长旅店老板：能够按其年龄与处境写服装和人物细节，不套样例的少年脸、黑衣或戒指。
- 只有设定没有图片的新人物：能够产出完整初设提示词，不能虚构身份附件，也不因缺参考图永远阻塞。
- 一张采用全身图扩展母图：无需先索要全部侧背参考，写清未知补全边界，不再次改衣。
- 同一客栈的主视角与反打：固定门窗、灯和家具，按相机朝向推导左右；场景板不套五表情布局。
- 只修母图中一个表情：定位格子，分清头部与视线，其他格和造型列为保持项，不重做全板。
- 后续另一集只要求一张关键帧：仍应用本规范，但只交该镜需要的完整正文，不无故启动整季和全角色资产。

报告规则来源、发现的问题和是否已解决。不要说“六次真实生图测试通过”。之后停止，等待用户给下一项创作任务。
